# Session 2026-05-16e — eslint-plugin-vuejs-accessibility : analyse statique a11y sur les templates Vue

## Contexte

Après avoir mis en place axe-core dans les tests Playwright (analyse a11y à l'exécution), on a voulu couvrir aussi les composants Vue qui ne sont pas forcément montés dès le démarrage — typiquement un composant dans un modal, ou derrière un toggle. axe-core ne peut scanner que ce qui est dans le DOM. ESLint, lui, lit le template statiquement.

## Ce que fait `eslint-plugin-vuejs-accessibility`

C'est un plugin ESLint dédié aux templates Vue. Il analyse le `.vue` comme source AST et remonte les violations WCAG 2.1 directement dans l'éditeur, au commit, et en CI — sans avoir besoin de rendre le composant.

Complémentarité avec axe-core :
- **axe-core (runtime)** : vérifie le DOM final après rendu, capte les problèmes de contraste, de hiérarchie de titres, d'éléments dynamiques
- **eslint-plugin-vuejs-accessibility (static)** : vérifie les templates Vue à la source, même pour des composants jamais visités par les tests E2E

## Intégration dans le projet

### Installation

```bash
npm install --save-dev eslint-plugin-vuejs-accessibility
```

### Configuration (`eslint.config.js`, flat config ESLint v9)

```js
import vueA11y from 'eslint-plugin-vuejs-accessibility';

export default [
    // ...
    ...vueA11y.configs['flat/recommended'],
    // ...
];
```

L'ordre compte : placer après `eslint-plugin-vue` et avant `eslint-config-prettier`.

## L'unique violation trouvée

Sur l'ensemble du codebase : **1 seule violation**, dans `LanguageSwitcher.vue`.

```
LanguageSwitcher.vue:90  vuejs-accessibility/form-control-has-label
<input type="search"> must have an accessible label
```

Le champ de recherche avait un `placeholder` mais pas d'`aria-label`. Le `placeholder` n'est pas un label accessible — il disparaît quand l'utilisateur tape, et les lecteurs d'écran ne le lisent pas toujours comme label.

**Fix** :

```vue
<input
    v-model="filter"
    type="search"
    :placeholder="t('language_switcher.filter_placeholder')"
    :aria-label="t('language_switcher.filter_placeholder')"
    ...
/>
```

On réutilise la même clé i18n que le placeholder — c'est la même phrase, mais l'`aria-label` reste présent même après que l'utilisateur a commencé à taper.

## Règles actives (flat/recommended)

Les principales règles que le preset active :

| Règle | Ce qu'elle vérifie |
|-------|-------------------|
| `form-control-has-label` | `<input>`, `<select>`, `<textarea>` avec label accessible |
| `anchor-has-content` | `<a>` avec texte ou `aria-label` |
| `anchor-is-valid` | `<a>` avec `href` valide (pas `href="#"`) |
| `click-events-have-key-events` | handlers `@click` accompagnés de `@keydown`/`@keyup` |
| `interactive-supports-focus` | éléments interactifs atteignables au clavier |
| `img-redundant-alt` | pas de "image" ou "photo" dans l'alt d'une `<img>` |
| `no-autofocus` | interdit `autofocus` (perturbe la navigation clavier) |
| `label-has-for` | `<label>` associé à un contrôle via `for` ou wrapping |

## Intégration dans le pipeline qualité

Le plugin s'intègre naturellement dans l'infrastructure existante :

- **lint-staged** : ESLint tourne à chaque `git commit` sur les `.vue` et `.js` modifiés → une violation a11y bloque le commit
- **CI (job `js`)** : `npm run lint:js` dans GitHub Actions → bloque la PR
- **`npm run check:full`** : inclus dans l'audit local complet

## Bilan : deux couches de protection a11y

```
Template Vue source  →  eslint-plugin-vuejs-accessibility  →  violations bloquées au commit
DOM rendu           →  axe-core (Playwright)              →  violations bloquées en CI
```

La première couche est plus rapide (pas besoin de lancer le serveur), la deuxième est plus complète (voit le rendu final, les contrastes, etc.). Les deux se complètent sans se chevaucher.

## Points notables

- Le plugin supporte le flat config ESLint v9 via `vueA11y.configs['flat/recommended']`
- Il faut importer l'objet par défaut (`import vueA11y from ...`), pas en named export
- `placeholder` ≠ label accessible — c'est le piège classique, et c'est exactement ce que le plugin attrape
- `aria-label` et `placeholder` ont des rôles distincts et **ne doivent pas contenir le même texte** : le placeholder est un hint court visible dans l'UI ("Filtrer…"), l'`aria-label` est une description du rôle du champ pour un lecteur d'écran ("Rechercher une langue"). Deux clés i18n séparées (`filter_placeholder` / `filter_aria_label`) — la commande `i18n:translate` propage la nouvelle clé à toutes les locales automatiquement.
