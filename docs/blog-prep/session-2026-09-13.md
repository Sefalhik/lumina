# Session 2026-09-13 — Le test qui certifiait le bug

## Contexte

Session ouverte sur une question de routine : « on a ajouté pas mal de locales, ce n'est pas le
moment de lancer les scripts d'internationalisation, ou faut-il attendre le seed LinkedIn ? »

La question en cachait deux — les deux commandes n'étaient pas du tout dans la même situation — et
la réponse a fait remonter quatre mois de dérive silencieuse, un défaut dans l'outil censé la
corriger, et un test qui couvrait exactement le chemin fautif tout en le certifiant.

Le volet précédent s'appelait « l'instrument qui dit vrai et ne dit rien ». Celui-ci est le cran
d'après, et il est plus retors : **un test qui dit vrai, qui couvre la bonne ligne, et qui grave le
bug dans le marbre au passage.**

---

## 1. Le repli qui rendait la panne invisible

Point de départ mesurable. `lang/fr/` contient sept fichiers ; les 23 autres locales en ont cinq.

```
admin.php    29 / 72 clés dans les 23 locales   → 43 manquantes
cv.php       absent des 23 locales              → jamais traduit
footer.php   absent des 23 locales              → absent depuis le 23 août
```

Première hypothèse, fausse : `config/app.php` déclare `'fallback_locale' => env('APP_FALLBACK_LOCALE', 'en')`,
et `lang/en/cv.php` n'existe pas non plus — donc Laravel devrait afficher la clé brute,
`cv.heading`, en toutes lettres sur la page.

Vérification plutôt qu'affirmation :

```
sv cv.heading          : Parcours
sv footer.social_aria  : Profil :network (nouvelle fenêtre)
fallback_locale        : fr
```

Le `.env` surchargeait le défaut. Pas de clé brute : **du français, bien formé, servi à 23 locales
sur 24.** Une page qui a l'air parfaitement normale, dans la mauvaise langue.

C'est la différence entre une panne et une dérive. Une panne se voit. Une dérive se *lit* — encore
faut-il lire le site en suédois.

Et le pire cas n'est même pas la page : ce sont les `aria-label` du pied de page. axe-core les scanne
à chaque exécution E2E, sur trois thèmes. L'attribut est rempli, non vide, correctement associé. Le
scan est vert. Il est en français pour un lecteur d'écran grec, et aucun contrôle d'accessibilité
automatique ne peut voir ça.

**Piste d'article** : les contrôles d'accessibilité vérifient la présence, pas la pertinence. Un
`alt` en français sur un site grec passe tous les tests.

---

## 2. Le second verrou, invisible depuis la surface

Sur le côté CMS, la réponse évidente était « attends le seed LinkedIn, la table est vide ». Vraie,
mais incomplète — `config('i18n.cms_models')` ne contenait que `HomepageContent`.

`Experience` déclarait `HasTranslations` et `$translatable = ['description', 'achievements']`. Tout
était prêt côté modèle. La commande ne l'aurait jamais parcouru, **et n'aurait rien dit** : elle
itère une liste, et ce qui n'y figure pas n'existe pas pour elle.

Le ticket qui a livré `Experience` avait pourtant documenté, dans le même commit, un piège de
routage sur `SetLocale` découvert en chemin. Le réflexe existe donc — pour ce qui nous a résisté,
pas pour ce qu'on a construit.

**Piste d'article** : on documente ce qui nous a surpris, jamais ce qu'on a fabriqué. Or c'est le
second qu'un lecteur futur cherchera.

---

## 3. La cause racine : l'outil qui fige sa propre erreur

Rattrapage lancé. La commande annonce `lang/fr/admin.php → lang/de/admin.php`, vingt-trois fois,
et se termine par `All translations completed.`

`ls -la lang/de/admin.php` : mtime au 17 mai. Rien n'a été écrit.

```php
foreach ($this->targetLocales as $locale) {
    if (! force && ! dry-run && file_exists($targetFile)) {
        if (! $this->confirm("lang/{$locale}/{$filename} already exists. Overwrite?")) {
            continue;                       // ← la locale est sautée
        }
    }
    // …traduction, écriture
}

if (! $this->option('dry-run')) {
    $this->cache->snapshotFile($sourceFile, $flatSource);   // ← inconditionnel
}
```

L'instantané est pris en fin de boucle **quoi qu'il arrive**. Trois chemins y mènent : une invite
d'écrasement refusée, une exécution non interactive (la CI), un échec d'API qui pose pourtant
`$exitCode = FAILURE`.

La source est alors marquée « traduite » sans qu'une seule cible ait été écrite. Le passage suivant
répond `unchanged, skipping` — **définitivement**.

C'est ce qui s'était produit en mai. Le ticket qui a ajouté les clés d'identité a lancé la commande,
les 23 invites sont tombées à « non », et la somme de contrôle a été estampillée. Depuis quatre
mois, l'outil censé corriger la dérive **refusait activement de regarder**.

La formule qui mérite l'article : l'outil ne ment pas sur ce qu'il a fait. Il ment sur ce qui reste
à faire — et c'est la seule chose qu'on lui demande.

## 4. Le cœur du sujet : le test qui certifiait le bug

Réflexe naturel : « les tests ont dû manquer ». Mesure :

```
I18nTranslateTest       25 tests
TranslationCacheTest    26 tests
CmsTranslateTest        16 tests
AnthropicTranslatorTest 14 tests
                        ──
                        95 tests
```

Une des zones les mieux dotées du projet. Et dans la liste des noms de test :

```
test_confirms_before_overwriting_existing_php_file_and_skips_on_no
```

Le chemin exact qui a cassé **a son test dédié**.

```php
$this->artisan('i18n:translate', ['--locale' => 'de'])
    ->expectsConfirmation('  lang/de/nav.php already exists. Overwrite?', 'no')
    ->assertSuccessful();

$kept = include $this->langDir.'/de/nav.php';
$this->assertSame('Alt', $kept['home']);   // le fichier n'a pas été écrasé ✓
```

Ce test est *correct*. Il vérifie exactement ce que son nom annonce : on répond non, le fichier est
préservé. C'est vrai, c'est utile, et c'est le bon test.

**Il s'arrête à la frontière de son propre nom.** Le défaut est trois lignes plus loin dans le code
de production. Le test ne l'affirme pas, ne le nie pas : il ne regarde pas.

Et il fait pire que l'ignorer. Ce `assertSuccessful()` grave dans le marbre qu'une exécution où
**rien n'a été écrit** doit retourner `0`. Le test ne rate pas le bug — il le certifie. Quiconque
corrigerait le code de sortie ferait rougir un test, et pourrait raisonnablement conclure qu'il
vient de casser quelque chose.

C'est le cœur du volet : **un test peut être juste, utile, bien nommé, couvrir la ligne fautive —
et transformer un défaut en comportement attendu.**

---

## 5. La faille structurelle sous les 95 tests

```php
$this->app->useLangPath($this->langDir);   // un dossier temporaire, monté au setUp
```

Les 95 tests travaillent sur une arborescence synthétique, construite au `setUp`, détruite au
`tearDown`. **Aucun ne regarde jamais `lang/` du dépôt.**

Le projet avait donc une réponse complète et rigoureuse à :

> « la commande fonctionne-t-elle ? »

et aucune réponse, pas même partielle, à :

> « mes traductions sont-elles à jour ? »

Deux questions différentes. Seule la seconde intéresse un visiteur suédois.

Personne n'avait décidé de ne pas poser la seconde. Elle n'a simplement jamais été formulée — parce
que la première était si bien traitée qu'elle donnait l'impression de recouvrir le sujet.

**Piste d'article, sans doute la meilleure de la série** : une suite de tests dense sur un outil
crée l'illusion de couvrir le domaine de l'outil. Tester le marteau n'est pas tester la charpente.

---

## 6. Ce qu'aucun garde-fou ne rattrapera

Le rattrapage effectué, vérification de parité : 7 fichiers × 23 locales, clés manquantes et clés
en trop. OK. Puis les placeholders — 3128 vérifiés, 6 écarts.

Cinq faux positifs, tous instructifs :

- `URL:n` — le génitif finnois, que le regex `/:[a-z_]+/i` prend pour un jeton
- `:attribute` deux fois en anglais, `:date` deux fois en slovène — des répétitions légitimes

La leçon technique : comparer des **ensembles**, jamais des occurrences.

Et un vrai défaut :

```
fr : Réessayez dans :seconds secondes.
fi : Yritä uudelleen {seconds} sekunnin kuluttua.
```

Le traducteur a converti la syntaxe de placeholder. Laravel ne substitue pas `{seconds}` : un
utilisateur finnois bloqué lit littéralement `{seconds}`. `git log` : présent depuis le commit
d'authentification initial. Et la valeur fautive est **dans le cache autant que dans le fichier** —
corriger l'un sans l'autre ne tiendrait pas un `--force`.

Puis, en relisant les traductions fraîches :

```
nl : Huidiige functie     ← « Huidige »
```

Une faute d'orthographe néerlandaise, générée le jour même. **Aucun des trois garde-fous prévus ne
peut la voir.** Ni la parité des clés, ni l'intégrité des placeholders, ni l'enregistrement des
modèles. Elle n'est visible que par quelqu'un qui parle néerlandais.

C'est la limite qu'il faut écrire dans le ticket, pour que personne ne s'y trompe dans six mois :
un test vert signifiera « les clés sont là et les jetons sont intacts ». Jamais « les traductions
sont bonnes ».

**Piste d'article** : le garde-fou automatique déplace la frontière de l'ignorance, il ne la
supprime pas. Le danger commence quand on oublie où elle est passée.

---

## Bilan

Une question de routine — « c'est le moment de lancer les scripts ? » — a produit :

- 43 clés × 23 locales + 2 fichiers entiers rattrapés
- un modèle traduisible câblé dans la configuration de traduction
- deux lignes de documentation qui se contredisaient depuis six jours
- un défaut de fond dans l'outil (LUMN-25)
- trois garde-fous à poser (LUMN-26)
- un bug finnois et une coquille néerlandaise
- un test à corriger, dont l'assertion actuelle est fausse

Aucun de ces éléments n'était rouge ce matin. Les sept contrôles qualité passaient. Ils passaient
déjà en mai.

## Pistes d'articles

1. **Le test qui certifie le bug** — quand une assertion correcte grave un défaut en comportement
   attendu. Le cas d'école du `assertSuccessful()`.
2. **Tester le marteau n'est pas tester la charpente** — 95 tests sur une commande, zéro sur l'état
   du dépôt.
3. **La dérive contre la panne** — pourquoi un repli bien configuré est le meilleur ami d'un bug qui
   dure quatre mois.
4. **L'outil qui fige son erreur** — le cache qui marque « fait » ce qui a échoué, et qui refuse
   ensuite de regarder.
5. **L'accessibilité vérifie la présence, pas la pertinence** — un `aria-label` français pour un
   lecteur d'écran grec.
6. **On documente ce qui nous a résisté, pas ce qu'on a construit** — le biais du commit qui
   explique le piège rencontré et oublie le service créé.
7. **Les faux positifs sont de la documentation** — le génitif finnois `URL:n` en dit plus long sur
   le domaine que le test qui passe.
8. **Où est passée la frontière de l'ignorance** — ce qu'un garde-fou déplace, et ce qu'il laisse
   intact. « Huidiige functie ».
