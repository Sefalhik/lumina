# Session 2026-09-13 (après-midi) — Ce qui est déclaré, ce qui est rendu

## Contexte

Suite de la matinée, qui s'était close sur « le test qui certifiait le bug ». L'après-midi part
d'une relecture de vues et dérive vers l'écriture de contenu, une archive LinkedIn vide, une
architecture de déploiement et deux défauts d'UX.

Un fil rouge s'impose au fil des heures, et c'est le frère du précédent. Le matin, des instruments
exacts rendaient des verdicts sans valeur. L'après-midi, **des choses parfaitement déclarées
n'arrivent jamais jusqu'au destinataire.**

Un anneau de focus dessiné et invisible. Cinq paragraphes présents dans le HTML et rendus en un
bloc. Un champ déclaré traduisible que personne n'écrit. Une archive nommée « export de données »
et qui n'en contient aucune. Une règle rangée dans mes mémoires et pas appliquée. Une traduction
grammaticalement correcte et contextuellement fausse.

**Déclarer n'est pas livrer.** C'est toute la distance entre un système qui dit ce qu'il fait et un
utilisateur qui reçoit quelque chose.

## 1. L'anneau de focus, dessiné et indiscernable

Laurent, en regardant simplement son site : *« mes boutons ne semblent pas vraiment changer de look
au focus »*.

Première tentation : conclure qu'il manque un style. Faux. DaisyUI le pose, et il survit jusqu'au
bundle de production — vérifié dans le CSS compilé, pas supposé :

```css
.btn                { outline-color: var(--btn-color, var(--color-base-content));
                      outline-offset: 2px }
.btn:focus-visible  { outline-width: 2px; outline-style: solid }
```

Sur un `.btn-primary`, `--btn-color` vaut la couleur primaire. Or ces boutons portent aussi une
classe maison :

```scss
.glow-box { box-shadow: 0 0 10px primary/80, 0 0 25px primary/50, 0 0 50px primary/20, …; }
```

**Un anneau de 2 px de couleur primaire, tracé 2 px plus loin, à l'intérieur d'un halo primaire
permanent de 50 px.** Chaque ligne de CSS fait exactement son travail. Le résultat est invisible.

Et personne ne pouvait le voir :

| Outil | Verdict |
|---|---|
| ESLint a11y | ne lit que les templates Vue, pas les Blade |
| axe-core, 3 thèmes | **WCAG 2.4.7 n'est pas automatisable** — aucun verdict rendu |
| Suite E2E | 47 règles `:focus-visible` livrées, **0 assertion sur le focus** |

**Piste d'article** : il existe des critères d'accessibilité qu'aucun outil ne peut trancher. Un
scan vert sur trois thèmes ne dit rien de celui-là, et rien ne le signale.

**Sous-piste** : `:focus-visible` ne se déclenche pas au clic souris. Qui teste son propre focus à la
souris conclut à un bug qui n'existe pas — ou passe à côté de celui qui existe.

## 2. Les cinq paragraphes qui n'en font qu'un

Nouvelle bio écrite pour la page d'accueil : cinq paragraphes, 960 caractères. Laurent remarque que
les boutons descendent très bas et demande s'il faut réduire la police.

La réponse est non, mais pas pour la raison attendue. Mesure sur la page réellement rendue :

```
retours à la ligne doubles dans le HTML : 4
balises <br> ou <p> internes            : 0
classe whitespace-pre-line              : absente de toutes les vues
```

Les sauts de ligne **sont** dans la source. HTML les écrase. Rien ne les rétablit. Les cinq
paragraphes sortent en un mur de 960 caractères — et la question posée (la taille de police) portait
sur le symptôme d'un défaut qui n'était pas celui qu'on croyait.

Réduire la police aurait rapporté 11 % de hauteur, deux lignes sur quinze, en poussant un texte déjà
à `text-base-content/70` vers la limite de contraste que la documentation du projet cartographie
elle-même. **Un problème de longueur de contenu n'est pas un problème de typographie.**

Le vrai correctif : couper. Le premier paragraphe (166 caractères, 3 lignes) devient l'accroche du
héros, juste avant les boutons ; les quatre autres descendent dans une section « À propos », en vrais
`<p>`. Gain mesuré : ~350 px, et les boutons remontent au-dessus de la ligne de flottaison.

**Piste d'article** : la question qu'on pose oriente la réponse qu'on reçoit. « Faut-il réduire la
police ? » présuppose que le texte est trop grand. Il était trop long, et surtout pas structuré.

## 3. Le test qui doit porter sur l'ordre, pas sur la présence

Le correctif ci-dessus appelle un garde-fou. Le réflexe serait :

```php
$response->assertSee('accroche')->assertSee('biographie');
```

Vert, et sans valeur : il resterait vert si toute la bio revenait dans le héros. C'est exactement la
régression à empêcher.

```php
$this->assertLessThan($cta, $lead, 'The hook must come before the buttons.');
$this->assertLessThan($body, $cta, 'The buttons must come before the biography.');
```

L'assertion porte sur **l'ordre dans le document**, pas sur la présence. Vérifié par mutation :
remettre le corps dans le héros fait tomber ce test et lui seul.

**Piste d'article** : c'est le prolongement direct du volet du matin. Un test qui vérifie qu'une
chose existe ne vérifie pas qu'elle est au bon endroit — et la plupart des régressions de mise en
page sont des déplacements, pas des disparitions.

## 4. La règle de gestion qui vivait dans un template

Relecture de la liste d'administration. Une ligne :

```blade
{{ $experience->isCurrent() ? __('admin.experience_current') : $experience->ended_at?->format('m/Y') }}
```

`CvService::period()` faisait déjà exactement ça pour la page publique, au même format. Une règle
métier, deux implémentations, deux langages, rien pour les tenir synchronisées.

Après déduplication, les 69 tests restaient verts. Sabotage :

```php

```

**La période de la liste d'administration n'était couverte par rien.** Deux tests ajoutés, dont un
qui lit la *même* chaîne sur les deux pages, afin qu'elles ne puissent plus diverger sans échec.

**Piste d'article** : le refactoring silencieux. Quand on déplace du code et que rien ne rougit, la
bonne conclusion n'est pas « c'était sûr » mais « ce n'était pas testé ».

## 5. Neuf recopies de ce que le framework faisait déjà

Toujours dans les vues :

```blade
route('admin.experiences.index', ['lang' => app()->getLocale()])
```

Neuf occurrences. Or `SetLocale` pose `URL::defaults(['lang' => …])` pour toute la requête. Mesuré :

```

```

Identique. La documentation technique décrit le mécanisme ; les vues l'ignoraient et le

c'est de la défiance — on repasse derrière l'outil « au cas où », et on crée le point de divergence
qu'on croyait éviter.

## 6. L'archive qui s'appelait « export de données »

Pour remplir le CV, Laurent fournit son archive LinkedIn. Contenu réel :

```
Invitations.csv
Registration.csv
Profile.csv
Articles/…/un-article.html
```

**Pas de `Positions.csv`.** Ni `Education.csv`, ni `Skills.csv`. C'est l'export « Basic », celui que
LinkedIn livre immédiatement ; le parcours professionnel n'est que dans l'archive complète, préparée
en 24 h et téléchargée séparément.

Trois choses utiles en sont quand même sorties : un écart entre l'intitulé de poste du site et celui
de LinkedIn, sur le champ précisément conçu comme référence croisée ; un lien retour pointant vers
un autre hôte ; et un résumé personnel bien meilleur que la bio du site.

Ce dernier point a ouvert une heure d'écriture — et la découverte que le canonical du site **suit
l'hôte de la requête** :

```
Requête sur http://autre-hote.example/fr/cv
→ <link rel="canonical" href="http://autre-hote.example/fr/cv">
```

Deux noms d'hôte servant le même contenu, chacun se déclarant canonique de lui-même.

**Piste d'article** : une question sur des données a produit un défaut SEO. Les trouvailles ne
viennent presque jamais de l'endroit où on cherchait.

## 7. Le champ déclaré traduisible que personne n'écrivait

En reprenant le seeder de la page d'accueil :

```php
public array $translatable = ['tagline', 'subtitle', 'bio', 'meta_description', 'skills'];
// le seeder écrit : tagline, subtitle, bio, skills
```

**`meta_description` est déclaré traduisible, déclaré fillable, et jamais écrit.** Un déploiement
neuf partait avec une balise description vide sur la page d'accueil — dans les 24 langues.

C'est la variante du défaut trouvé le matin sur `Experience`, absent de `cms_models` : un modèle
promet une capacité, et personne ne la branche. Le modèle ne ment pas. Il déclare une intention que
rien n'oblige à tenir.

**Piste d'article** : `$translatable`, `$fillable`, `$casts` — des déclarations que le framework ne
vérifie jamais contre l'usage réel. Une promesse sans contrat.

## 8. Le cache qui fusionne quand on croit qu'il remplace

Pipeline de contenu : écrire le français, traduire, figer. Après avoir semé le nouveau texte :

```
tagline  locales: fr,en,bg,cs,da,de,…   ← 24 locales, toujours
```

`setTranslations()` **fusionne**. Les 23 locales portaient encore les traductions de l'*ancien*
texte, avec le nouveau français à côté. Exporter à cet instant aurait figé l'incohérence dans un
fichier versionné, livré à chaque déploiement, pour toujours.

C'est le piège le plus vicieux de la journée : chaque opération réussit, aucune n'échoue, et l'état
final est faux.

**Piste d'article** : les API dont le nom suggère le remplacement et qui font l'ajout. `set` au
pluriel ne veut pas dire « remplace l'ensemble ».

## 9. La décision d'architecture : l'API hors du chemin de déploiement

Tentation évidente :

```bash
migrate --force && db:seed --force && cms:translate
```

Écartée, et les raisons valent d'être écrites : un secret d'API en production, un coût par
déploiement, plusieurs minutes de latence, une page à moitié traduite si un appel échoue en cours de
route, et un résultat différent à chaque fois.

La forme retenue appelle l'API **une fois, à l'écriture**, et fige les 24 locales dans un fichier
versionné. Le déploiement ne fait plus que lire. Prouvé par le test, et pas n'importe comment :

```php
Http::fake();
$this->runSeeder();
Http::assertNothingSent();
```

Un `Http::fake()` seul laisserait passer un appel réel déguisé en 200. C'est `assertNothingSent()`
qui prouve quelque chose.

**Bénéfice non anticipé** : les traductions passent désormais par `git diff`. C'est le seul endroit
où un humain peut les lire avant un visiteur.

## 15. Un générateur de code qui n'échappait que la moitié de ses entrées

La commande écrit du PHP exécutable, `require`é au déploiement. Les valeurs étaient échappées —
vérifié sur une chaîne hostile mêlant apostrophes, antislashs et sauts de ligne : aller-retour

Les **clés** ne l'étaient pas.


**Piste d'article** : la défense en profondeur est intestable par construction. Si la première
barrière tient, la seconde n'est jamais sollicitée — et un outil de couverture la déclarera
couverte.

## 18. Le middleware que la documentation décrivait et qui n'existait pas

`logging-conventions.md`, section 5, décrit un middleware de corrélation et en tire une instruction
adressée à tout le code :

> *Service code does **not** need to repeat these — they appear automatically in every log record.*

```
app/Http/Middleware/   →   EnsureTwoFactorVerified.php, SetLocale.php
grep "request_id|Context::add" app/ bootstrap/   →   aucune occurrence
```

Vérifié sur une ligne réellement émise : ni `request_id`, ni `user_id`. **Les 61 appels de log du

conforme.**

**Piste d'article** : j'ai failli livrer un chiffre faux sur un problème réel. L'outil de mesure
improvisé est le premier à vérifier.

## 19. Semer des données a révélé 373 violations

La suite E2E ne semait que l'identité du site. La table du contenu d'accueil restait vide, donc la
page rendait ses replis : **la section « À propos » ne s'affichait jamais**, et la grille de

Écrite, puis pas appliquée — à la fonctionnalité livrée le jour même.

Une fois le contenu semé, trois masques sont tombés d'un coup :

**Piste d'article, forte** : une base de test vide est un décor de cinéma. Tout ce qui n'apparaît
qu'avec des données échappe à l'inspection, et la suite reste verte en ne regardant rien.

## 20. Le test qui mesure l'écran plutôt que le DOM

Le correctif d'UX de la journée — remonter les boutons au-dessus de la ligne de flottaison — n'était
protégé par rien. PHPUnit épingle l'ordre des éléments dans le document ; **un ordre correct avec
les boutons 350 px plus bas satisferait tous les tests serveur et resterait le bug.**

```js
expect(box.y + box.height).toBeLessThanOrEqual(viewport.height);
expect(await page.evaluate(() => window.scrollY)).toBe(0);
```

`toBeVisible()` est vrai pour un élément situé trois mille pixels plus bas. Seule la position
mesurée dit quelque chose.

## 21. Relire ce qu'on a soi-même écrit

Dernière heure : relecture des traductions des cinq locales indexables. **Neuf défauts nets.**

- du **français resté dans le texte** néerlandais — « biocortex actif » au lieu d'« actief »
- trois **calques** de « sous la pluie » : `unter dem Regen`, `onder de regen`, et `on neons` en
  anglais, où le substantif pluriel n'existe pas
- `foutenlogboek` — un *journal* d'erreurs — pour une trace d'appels
- `nevel` — de la *brume* — pour de la bruine, dans la phrase à laquelle l'auteur tenait le plus

Et la cause, trouvée dans le prompt :

```php
You are a professional translator specializing in UI localization.
...
- Keep proper names, brand names, and technical terms untranslated
```

**Le même prompt sert aux deux commandes.** Une biographie littéraire part chez un traducteur qui se
déclare spécialiste d'interface. Et la règle sur les termes techniques est **exactement** ce qui a
laissé « actif » en français : le modèle l'a classé comme partie d'un terme forgé.

**Une règle du prompt a causé un des défauts qu'on lui reproche.**

Reste la limite que je ne peux pas franchir, et qu'il faut écrire : ces traductions ont été
produites par le même modèle que celui qui les relit. Les erreurs systématiques sont invisibles par
construction — on les regénérerait à l'identique en les croyant justes. Ce qui a été attrapé ici,
ce sont des erreurs d'une *autre* nature : des calques et des glissements lexicaux, visibles quand
on lit pour comprendre au lieu d'écrire pour que ça coule.

**Piste d'article, la plus inconfortable de la série** : un relecteur qui est aussi l'auteur ne
peut pas voir ses propres angles morts. C'est vrai d'un modèle, et c'est vrai d'un développeur qui
relit son propre code.

Deux détails achèvent le tableau. Le modèle employé est **Haiku 4.5** — parfait pour « Enregistrer »
→ « Speichern », inadapté à 960 caractères de prose à registre marqué. Et il n'y a **aucun prompt
système** : tout est empilé dans le tour utilisateur, sans qu'on dise jamais au traducteur à qui
appartient le site ni dans quelle voix il parle.

La décision produit qui en découle vaut d'être notée, parce qu'elle va à l'encontre de l'instinct :
**on garde les 24 locales, prose comprise.** Restreindre le contenu aux cinq langues relues aurait
servi du français sous une URL `/sv/` portant un `hreflang` suédois — exactement la dérive corrigée
le matin même. Mieux vaut du suédois imparfait que du français étiqueté suédois. Contrepartie
assumée : dix-neuf locales que personne ne lira jamais.

## Pistes d'articles

1. **Déclarer n'est pas livrer** — l'article-chapeau. Tout ce qui est correctement annoncé et
   n'arrive jamais : un anneau de focus invisible, des paragraphes écrasés, un champ traduisible que
   personne n'écrit, une archive vide.
2. **Les critères que l'automatisation ne peut pas trancher** — WCAG 2.4.7, le contexte d'une
   traduction, la perception d'une couleur. Où s'arrête la frontière de l'outillage.
3. **Tester l'ordre, pas la présence** — la suite directe du « test qui certifiait le bug ».
4. **Le refactoring silencieux** — quand rien ne rougit après un déplacement, ce n'est pas une
   preuve de sûreté.
5. **`set` au pluriel ne veut pas dire remplacer** — les API dont le nom ment sur la sémantique.
6. **Sortir l'API du chemin de déploiement** — pourquoi un déploiement qui appelle un service
   externe pour fabriquer son contenu est un déploiement qui peut livrer à moitié.
7. **La documentation interne pourrit aussi** — la note défensive écrite une fois, jamais
   revérifiée, qui interdit un outil qui marche.
8. **Le test trop strict est un faux positif industrialisé** — et il coûte plus cher que l'absence
   de test.
9. **La question oriente la réponse** — « faut-il réduire la police ? » présuppose un diagnostic.
10. **Les outils globaux dans un travail cloisonné** — régénérer « tout » sur une branche qui ne
    possède qu'une partie.
11. **La moyenne absorbe le trou** — pourquoi un seuil de couverture global monte quand le projet
    grossit, pas quand il s'améliore.
12. **La défense en profondeur est intestable** — et l'outil de couverture la déclarera couverte.
13. **Une base de test vide est un décor de cinéma** — tout ce qui n'apparaît qu'avec des données
    échappe à l'inspection.
14. **Mesurer l'écran, pas le DOM** — l'ordre correct avec le bouton hors champ satisfait tous les
    tests serveur.
15. **Le relecteur qui est aussi l'auteur** — sur les angles morts qu'on ne peut pas voir en
    relisant sa propre production. Modèle ou humain, même limite.
